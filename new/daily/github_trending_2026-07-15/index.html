7月12日，安全研究团队 Cereblab 发布针对 Grok Build CLI 0.2.93 的网络流量分析。测试显示，在普通消费者账户下，Grok Build 会将完整的已跟踪 Git 仓库打包上传，其中包括代理未读取的文件和 Git 提交历史；被工具读取的 .env 测试文件内容也会未经脱敏地出现在模型请求及会话存档中。关闭“用于改进模型”选项后，相关仓库上传仍然发生。研究只能证明数据被传输和服务器接收，不能证明 xAI 将其用于模型训练，也不能证明所有账户均采用相同行为。

7月13日，研究者使用相同版本客户端再次进行了六次测试。新的服务器配置将代码库上传和追踪上传设为关闭，测试中未再出现 /v1/storage 仓库上传请求。这表明 xAI 可能已经通过服务器端配置进行了调整，但当时尚未公布调整范围、适用账户及此前数据的处理方式。

随后，xAI回应称，启用零数据留存（ZDR）的团队不会留存 Grok Build 的追踪和代码数据，通过 API Key 使用 Grok Build 时同样遵循 ZDR。未启用 ZDR 的用户可以在 CLI 中运行 /privacy，查看或关闭数据留存；关闭后，系统还会删除此前同步的数据。xAI官方文档确认 /privacy 可用于查看或切换隐私与数据留存状态，并表示团队级 ZDR 开启后，推理层不会持久保存提示词、代码或响应。


目前，xAI尚未在公开更新日志中详细说明此次事件涉及哪些版本和账户，也未公开此前上传数据的具体留存期限、删除流程及服务器端调整的完整覆盖范围。最新公开更新日志列出的版本为7月12日发布的 Grok Build 0.2.98。

有说法称 DeepSeek 正在自研推理ASIC芯片？规格、流片和量产的时间节点？

DeepSeek目前已经组建了一个团队专门研发推理芯片，现在这颗芯片采用 ASIC架构，主要设计是在多个加速单元上，根据 DeepSeek现有的模型以及即将推出的 下一代架构，增加了许多专用的向量加速单元。同时，这颗芯片支持原生的 FP4。在互联带宽和内存容量方面，指标设定都比较高。也有消息称可能会采用 memory 的3D 堆叠技术，但最终方案尚未确定。流片时间预计在 2027 年第一季度。目前还未最终决定首颗芯片的制程，但已为高端制程做了准备。

有说法智谱也要考虑自研芯片？他们的设计合作代工方和时点是什么情况？

据悉智谱是在考虑做芯片。不过团队还处于非常早期阶段。有自己的芯片能更好保障模型推理业务能获得更大市场份额和更好的用户体验。不过智谱现在还没有急于下场，预计2027年可能开始设计，2028年晚些时候才可能量产。智谱模型出海有问题，被列入名单，海外部署只能依赖第三方，这部分收益无法获得，自己部署也要绕很多弯，成本和经济效益都不理想，因此智谱才考虑自研芯片以支持海外模型部署。
